# Domain docs

This checkout uses a single-context layout. Paths below are relative
to this checkout's root.

## Before exploring

Read `GLOSSARY.md` and ADRs in `docs/adr/` relevant to the work.

If `GLOSSARY-MAP.md` exists, follow its pointers to relevant glossaries.

If these files are absent, proceed silently. The domain-modeling skill
creates glossaries and ADRs when terms or decisions are resolved.

## Vocabulary and decisions

Use the glossary's terms in issues, proposals, hypotheses, and tests.
For missing concepts, reconsider invented terminology or note a real
gap for domain-modeling.

Explicitly surface conflicts with an existing ADR, identifying the ADR
and explaining why its decision may need to be revisited.
